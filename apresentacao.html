js/storage.js — Módulo IIFE

Storage — padrão IIFE e CRUD básico

O arquivo usa um IIFE (Immediately Invoked Function Expression) — uma função que se executa sozinha e retorna só a API pública. Isso protege as funções internas de serem acessadas de fora. linhas 7–78

  • get(key) — lê e faz parse automático do JSON
  • set(key, data) — serializa para JSON e salva

Introdução
Minha parte no projeto
Minha responsabilidade foram quatro arquivos. O carrinho.html, que é a página do carrinho de compras. O css/carrinho.css, com todo o layout e estilo visual da página. O js/storage.js, que é o módulo compartilhado de CRUD no localStorage usado por todo o grupo. E o js/main.js, que injeta o header e footer automaticamente em todas as páginas, atualiza o badge de quantidade no ícone do carrinho e exibe notificações na tela.
carrinho.html — Estrutura
Estrutura HTML da página linhas 19, 26, 80, 105
A página carrega dois arquivos CSS em ordem específica. Primeiro o styles.css do grupo, depois o carrinho.css específico desta página — assim o carrinho pode sobrescrever estilos globais quando necessário. O HTML tem um banner page-hero com o título e um contador de produtos atualizado pelo JavaScript. A div conteudo-carrinho começa completamente vazia no HTML — o JavaScript monta todo o conteúdo dinamicamente. A ordem dos scripts também é obrigatória: storage.js primeiro, depois main.js, e só então nosso código, porque o carrinho usa funções que só existem depois que esses arquivos carregam.
css/carrinho.css — Layout
Grid responsivo do carrinho linhas 14–36
O layout usa CSS Grid. No mobile, que é o padrão, temos uma coluna única com a lista de produtos em cima. No desktop, acima de mil e vinte e quatro pixels, o grid passa para duas frações para os produtos e uma fração para o resumo do pedido, usando a propriedade grid-template-columns. O elemento main tem altura mínima de sessenta por cento da viewport para empurrar o footer para baixo mesmo quando o carrinho está vazio.
css/carrinho.css — Cards
Estilos dos cards e controles linhas 78–315
O card de produto faz um override do padding global de vinte e quatro para dezesseis pixels, deixando os cards mais compactos. A imagem do produto usa object-fit cover para não distorcer em nenhuma tela. O botão menos fica com opacidade de zero ponto quatro e cursor not-allowed quando desabilitado — o JavaScript insere o atributo disabled e o CSS cuida da aparência. O card de resumo do pedido tem position sticky com top de oitenta pixels, considerando o header de sessenta e quatro pixels mais uma folga, para o resumo acompanhar o scroll da lista de produtos.
js/storage.js — Módulo IIFE
O módulo Storage e o padrão IIFE linhas 7–78
O storage.js usa um padrão chamado IIFE — uma função que se executa imediatamente e retorna apenas a API pública, protegendo as funções internas. As operações básicas são get para ler, set para salvar serializado em JSON, remove para apagar uma chave e clear para apagar tudo. Tem também uma função privada _parse com try e catch que converte a string JSON de volta para objeto sem travar a aplicação se o valor estiver corrompido.
js/storage.js — Helpers de Lista
Operações sobre arrays no localStorage linhas 41–74
O getList retorna o array ou array vazio se a chave não existir, nunca null. O addToList gera um ID automático usando Date.now se o item não tiver um. O updateInList usa findIndex para localizar o item e o spread operator para mesclar só os campos que mudaram, sem perder os outros dados. O removeFromList usa filter para criar um novo array sem o item removido. E o findInList retorna o item pelo ID ou null se não encontrar.
js/main.js — Header e Footer
Injeção automática de header e footer linhas 6–91
O main.js escuta o evento DOMContentLoaded que dispara assim que o HTML é processado, sem precisar esperar as imagens. A função injectHeader cria o elemento header com logo, menu de navegação e ícone do carrinho usando createElement, innerHTML e body.prepend. A função injectFooter cria o footer com grid de quatro colunas, incluindo o ano atual gerado automaticamente com new Date().getFullYear. A função highlightActiveNav lê o nome da página atual na URL e adiciona a classe active ao link correspondente no menu.
js/main.js — Badge e Toast
Contador do carrinho e notificações linhas 94–120
A função updateCartBadge lê o localStorage, soma as quantidades com reduce e atualiza o número no ícone do carrinho no header, exibindo ou escondendo o badge. A função mostrarToast exibe uma notificação no topo da tela por três segundos usando classList e setTimeout para remover depois. O carrinho chama mostrarToast depois de remover um produto ou limpar o carrinho, confirmando a ação para o usuário.
Critério: Árvore DOM
Manipulação do DOM no carrinho linhas 128, 173, 316
O addEventListener load garante que o script só executa depois que a página inteira carregou. Com getElementById selecionamos os elementos pelo ID. Com textContent atualizamos o texto do contador de produtos no banner. Com innerHTML inserimos o HTML completo dos produtos na div vazia.
Carrinho — Função Principal
renderizarCarrinho — a função que controla tudo linhas 155–317
Esta função é chamada toda vez que algo muda. Lê o array do localStorage, atualiza o contador no banner com if else if e else. Se o carrinho estiver vazio, exibe o card de aviso e para a execução com return. Se tiver produtos, calcula subtotal com reduce, aplica frete com operador ternário — grátis acima de duzentos reais —, monta o HTML com forEach e insere via innerHTML.
Aula 6 — forEach / Template Literal
forEach e o card de cada produto linhas 258–404
Para cada produto o forEach chama montarHtmlProduto, que usa template literal — crases com cifrão e chaves para inserir variáveis dentro do HTML sem concatenar com o operador mais. O botão menos fica desabilitado quando a quantidade é um, usando operador ternário que insere o atributo disabled ou uma string vazia. A função auxiliar resolveImg corrige automaticamente o caminho das imagens, adicionando o prefixo ../ quando necessário, pois o carrinho agora fica dentro da subpasta checkout e os caminhos relativos precisam subir um nível.
Aula 6 — reduce()
calcularSubtotal com reduce linhas 412–417
O reduce percorre o array acumulando um resultado numérico, começando em zero. Para cada produto soma preço vezes quantidade no acumulador e retorna o total.
Aula 6/7 — Math.max, confirm, localStorage
Alterar, remover e limpar linhas 441–509
O Math.max de 1 e a nova quantidade garante que nunca vá abaixo de um. O confirm exibe caixa nativa OK e Cancelar antes de remover ou limpar, evitando ação acidental. O removeFromList remove um produto pelo ID. O Storage.remove apaga a chave inteira — mais eficiente do que remover item por item. Em ambos os casos o mostrarToast do main.js confirma a ação com notificação verde.
Conclusão
Resumo dos meus quatro arquivos
O storage.js fornece o módulo de persistência para todo o grupo usando o padrão IIFE. O main.js garante que header, footer, badge e notificações funcionem em todas as páginas. O carrinho.css define o grid responsivo, os cards e o resumo sticky. E o carrinho.html une tudo usando DOM dinâmico, localStorage, forEach, reduce, operador ternário, Math.max e confirm.
Fluxo do Projeto
Como as páginas se conectam ao carrinho
O Guilherme criou o catálogo de produtos padrão diretamente no storage.js, com seis produtos que são carregados automaticamente no localStorage na primeira visita. Na página inicial, index.html, e também em produtos/produtos.html, quando o cliente clica em Comprar a função addCart é chamada. Essa função usa o Storage.getList, Storage.updateInList e Storage.addToList do storage.js — que é minha responsabilidade — para gravar o produto no localStorage. Ela também chama updateCartBadge e mostrarToast do main.js — que também é minha responsabilidade. O carrinho, que é minha parte central, lê esse localStorage, exibe os produtos, permite editar quantidades, remover itens individuais e limpar tudo de uma vez. Quando o cliente decide finalizar, o botão leva para o fluxo de checkout criado pela Estella: checkout, entrega, pagamento, revisão e confirmação do pedido. O agendamento.html tem fluxo completamente independente e não interage com o carrinho. A Nicolle também entregou as páginas de serviços: banho.html, hotel.html e veterinario.html — os links do footer do main.js foram ativados apontando para essas páginas.
